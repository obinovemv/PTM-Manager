# PTM Manager v2.2.2 — Device Trust & Setup Fix

## Root cause fixed
The Manager backend health endpoint could remain healthy while /device-setup returned HTTP 500 because the route rendered device_setup.html but the v2.2.x release payload/installer did not install that template.

## Device Setup
- Installs a dedicated responsive Device Setup & Security page.
- Preserves the existing authenticated root-CA, Windows ZIP, Apple mobileconfig and Android CA endpoints.
- If Portal/static/ptm-root-ca.crt is missing during upgrade, the installer attempts to export the existing PTM Root CA public certificate from the Windows trusted-root stores.
- Never distributes a CA private key.
- Windows setup verifies SHA-256 before importing into LocalMachine Trusted Root and validates DNS + HTTPS.
- Apple profile guidance includes the required manual Full Trust step for manually installed profiles.
- Android receives the public CA certificate for device certificate installation.
- Warranty and Quotation PC Setup & Security links continue to route centrally to manager.ptm.local/device-setup.

## Recommended managed deployment
Domain-joined Windows PCs should receive the same PTM root CA through Active Directory Group Policy rather than requiring per-PC manual setup. Apple fleets should use MDM/Configurator where available.

## Infrastructure
No DNS, Caddy routing, Tailscale or port changes are made by this release.
